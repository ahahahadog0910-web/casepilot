# CasePilot 技术演进

## 目标架构

```text
文档上传/粘贴
      |
      v
文档解析层  ->  需求结构化层  ->  测试设计层  ->  评审与编辑
      |              |                |              |
      +-------------- 模型适配层 ------+              |
                                                     v
                                      Excel / XMind / API 导出
```

## 分层原则

### 1. 输入层

负责处理文本、Markdown、DOCX、PDF 和设计稿说明。输入层只负责提取内容和基本元数据，不直接生成测试用例。

### 2. 需求结构化层

将原文转换为角色、功能、流程、业务规则、状态、异常、权限、外部依赖和非功能要求。结构化结果应保留原文片段，支持追溯。

### 3. 测试设计层

根据测试策略生成测试点和测试用例。功能、边界、风险、安全、易用性等维度应是可配置的，不依赖单一模型的固定输出。

### 4. 交付层

同一份 `TestPlan` 支持多个导出格式。Excel 偏向执行和评审，XMind 偏向测试点讨论。单位差异通过模板和规则配置表达。

## 多模型调试

后续增加“模型实验”能力时，建议为每次运行记录：

- 输入文档版本
- 模型适配器 ID 和模型名称
- 系统提示词/任务提示词版本
- 生成参数
- 原始输出和标准化输出
- 人工评分、缺陷标记和最终采用结果

这样可以在同一份需求上比较不同真实模型，而不影响正式项目中的测试方案。
